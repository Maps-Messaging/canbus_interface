# Independent CANboat conformance vectors

Related work: MSG-422. These are test resources only. No driver, catalogue, codec,
transport implementation, dependency or server behaviour is changed.

## Provenance

The factual wire bytes and expected values are curated from CANboat commit
[`5b8340403e009b935f6a398b1ef0244a03e3d128`](https://github.com/canboat/canboat/tree/5b8340403e009b935f6a398b1ef0244a03e3d128/analyzer/tests)
(version 9.1.0, matching the bundled catalogues). Each vector identifies its input
file, output file and input line. Expectations are never generated by Maps' encoder
or decoder. Tests are offline and require no physical CAN interface.

The 72 cases use `pgn-unit-coverage`, `pgn-si-units`, `pgn-string-encoding`,
`pgn-decimal`, `pgn-bitlookup-64`, `pgn-130823-directory`, `j1939-unit-coverage`
and `j1939-temperature` inputs and their corresponding expected output files.

The input/output projections preserve upstream values while using the catalogue's
canonical field IDs. Lookup objects containing a numeric `value` retain that number.
Display-only lookup labels are not guessed into numbers. Bitlookup numeric values
are combined into the equivalent integer mask, including values above signed 64-bit
range. Hexadecimal binary output is represented as base64, matching the public API.

## Units and precision

CANboat's SI-output mode and Maps' declared field units are different representations.
`normalization` records every affected expected field. The explicit conversions are:

| CANboat SI value | Maps declared unit | Conversion |
| --- | --- | --- |
| joules | kWh | divide by 3,600,000 |
| coulombs | Ah | divide by 3,600 |
| cubic metres | L | multiply by 1,000 |
| cubic metres per second | L/h | multiply by 3,600,000 |
| revolutions per second | rpm | multiply by 60 |
| metres per second | km/h | multiply by 3.6 |
| fraction | %, ppt, ppm | multiply by 100, 1,000, 1,000,000 respectively |
| pascals per second | Pa/hr | multiply by 3,600 |
| kilograms per second | kg/h | multiply by 3,600 |
| pascal seconds | cP | multiply by 1,000 |
| kilograms per cubic metre | g/cm3 | divide by 1,000 |
| radians | degrees | multiply by 180/pi |
| radians or radians per second | semi-circle or semi-circle/s | divide by pi |

Geographic latitude/longitude remain degrees as in the upstream output. Dynamic
key-value fields use the unit associated with their particular key: Victron deepest
discharge is Ah and its charge alarm is percent; Mercury fuel-used is litres and
throttle is percent; B&G tacking performance is percent.

Numeric tolerances are half the final decimal place printed by upstream, propagated
through the stated conversion, with a 1e-12 arithmetic floor for decimal values.
Integer values and 64-bit masks are checked exactly. No decoder result is used to
choose either the expected value or its tolerance.

## Derived boundary cases

The ten short DSC inputs are below the catalogue's 60-byte minimum. They assert
explicit rejection rather than adopting the upstream analyzer's permissive partial
output as a complete supported packet.

Nine additional DSC cases retain those input prefixes unchanged and supply a
complete fixed layout: unspecified fields are unavailable, and the telephone LAU
string at byte 21 is empty (`02 01`). This makes address and discriminator semantics
testable without failing earlier on minimum length. The malformed decimal-pair case
preserves the existing strict rejection of pairs above 99; CANboat instead omits that
value. This difference is explicitly recorded in the vector.

The all-undefined LAU fixture expects empty strings, which is the existing Maps
representation; upstream omits those fields. Two further literal cases exercise
unsigned 16-bit upper bounds and unavailable/error/reserved sentinel codes.

The two Navico directory cases retain every literal upstream CAN frame, including a
32-frame response. The other NMEA payload cases also pass through manually constructed
single/fast framing headers, independently of `FramePacker`. No test derives the
expected JSON by decoding an encoded payload or obtains expected bytes by encoding
its own decoded output. Independent encoding checks cover AC quantities, position
deltas, signed percentages, 64-bit masks and DSC address prefixes.

## Known failures exposed by this suite

PGN 129808 nine-digit DSC addresses differ from the independent expected values:

| Expected address | Current decoded address |
| --- | --- |
| `235076393` | `2350763930` |
| `244060807` | `2440608070` |
| `002241024` | `0022410240` |
| `152004051` | `1520040510` |

Encoding those nine-digit addresses also left-pads them, producing bytes different
from the known wire prefixes. Ten-digit geographic/group values remain ten digits;
they must not be fixed by blindly trimming every trailing zero. Four value cases
therefore fail in direct decoding, framed decoding and independent encoding: twelve
failing test invocations for the same address-handling problem. These checks remain
enabled. Production correction requires a separately agreed change.

## Coverage limits

`coverage.csv` lists **all 729 definitions** in both pinned catalogues, including
fallbacks, with positive-value and rejection-vector references from this new corpus.
An empty vector column means this corpus has no independent oracle for that variant;
it does not mean the variant is unsupported. A populated column records evidence,
not a guarantee that the test passes; the DSC failures above are retained.

This corpus provides value oracles for **33 NMEA variants across 27 PGNs** and
**10 J1939 variants across 10 PGNs**. Twelve of those NMEA PGNs were absent from the
legacy 113-PGN catalogue: 61184, 65005–65008, 126720, 130567, 130818, 130820,
130823–130825. Existing `CanboatGoldenVectorsTest` supplies additional independent
cases, while the existing migration tests exercise every concrete catalogue variant
with generated round trips. These forms of evidence are distinct.

This is broader, independently checked coverage, not a claim of hardware validation
or complete independent conformance for every PGN, field or variant. J1939 cases
cover payload codecs only; they do not add or certify J1939 transport.

Run the new tests:

```sh
mvn -pl canbus-nmea2000 -am test -Dtest=CanboatConformanceVectorsTest -Dsurefire.failIfNoSpecifiedTests=false
```

Run the entire library with `mvn clean test`. A clean build is useful after switching
from branches containing other test classes, so stale compiled tests are not run.
